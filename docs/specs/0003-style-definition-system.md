# Spec 0003 — Style Definition System (S1a)

**Status:** v5 — post-build fixes applied, re-sealing
**Owner:** both
**Followed by:** S1b — Paper K-pop reference pack

## Goal

Prove that a style can be defined as a complete, machine-checkable, reusable package — independent of any single video — before any renderer or film is built.

S1a ships the **definition machine**, not a style. Paper K-pop is S1b.

## What changed in v4

- The 13-field abstraction is gone. The 27 decisions map directly to a file and JSON pointer.
- A `bindings` block makes hashes real: brief, template, contract and pack.
- `style:approve` rewrites the card and writes a hash-bound sign-off.
- `style:resolve` asserts coverage, difference and determinism, and takes `--seed`.
- Both resolver formats have a `beatRoleMap`; the resolver consumes a generic content brief, so no slot map is needed.
- `TYPE_ROLES` and `PHYSICS` close the last open vocabularies.
- The report has a real finish: open the card, then approve.
- The card requires an ANTI reference and a hero specimen above the fold.
- `keepsake` is a family archive, not a wedding.
- `styles/paper-vows` is marked legacy for S1a; S1b migrates it.
- The gate is binary: both verifiers must return GO **and** score at least 9/10.

## The pack

Six authored artifacts, recipes, and a generated sign-off:

```
styles/<style-id>/
  BRIEF.md              frozen input, hashed
  STYLE.md              intent, invariants, signature, refusals, not-for
  tokens.json           medium, colour, type, layout, motion, sound, seed
  capabilities.json     identity, limits, adaptation, assets, runtime, evidence, proof, bindings
  recipes/*.json        one file per shot, with a composition program
  card.html             the one-page human artifact
  signoff.json          generated by style:approve; absent until approved
```

Template:

```
styles/_template/
  BRIEF.md
  STYLE.md
  tokens.json
  capabilities.json
  recipes/_example.json
  card.html
```

## Recipe contract

```json
{
  "id": "page_turn_spread",
  "beatRoles": ["portrait", "detail"],
  "duration": { "min": 4, "max": 10, "default": 6 },
  "camera": { "move": "push_in", "from": 1.0, "to": 1.04, "ease": "easeOut" },
  "slots": ["photos.hero", "content.caption"],
  "assets": ["frame.archive", "texture.fiber"],
  "composition": [
    { "op": "layer", "id": "paper", "z": 0 },
    { "op": "image", "slot": "photos.hero", "frame": "frame.archive" },
    { "op": "text", "slot": "content.caption", "typeRole": "caption" },
    { "op": "transition", "kind": "page_turn" }
  ],
  "transitionOut": "page_turn",
  "failureModes": ["caption longer than two lines", "photo below print resolution"]
}
```

Text ops reference only slots. Literal copy is allowed only in `card.html`, labelled `SPECIMEN`.

## Bindings and hashes

`capabilities.identity.bindings`:

```json
{
  "briefHash": "sha256:...",
  "templateHash": "sha256:...",
  "contractHash": "sha256:..."
}
```

`style:check` recomputes all three and computes `packHash` over every pack file except `signoff.json`.

- A mismatch is a hard failure.
- `style:approve` writes `signoff.json` with `by`, `date`, `version`, `packHash`, `briefHash`, `templateHash`, `contractHash`, and rewrites the card's sign-off block.
- Any change after approval makes `packHash` differ and returns `REVIEWABLE — changed after approval`.

## Reuse test: `style:resolve`

The resolver consumes a **generic content brief**, so formats do not need a slot map:

```json
{
  "content": {
    "title": "...", "subtitle": "...", "names": "...", "date": "...", "venue": "...",
    "body": "...", "caption": "...", "hashtag": "...", "rsvp": "...", "monogram": "..."
  },
  "photos": { "hero": "...", "supporting": [] }
}
```

```
npm run style:resolve -- --style styles/_examples/keepsake --seed 42 \
  --brief fixtures/resolve/family-archive.json --format formats/keepsake-book/format.json \
  --brief fixtures/resolve/family-archive-2.json --format formats/keepsake-gallery/format.json
```

Assertions:

1. Every slot in every selected recipe resolves non-empty.
2. Every format beat maps to at least one recipe through `beatRoleMap`.
3. Every asset resolves in `capabilities.assets`.
4. The two briefs produce different plans; at least one slot value differs.
5. Same seed twice produces byte-identical JSON.
6. A different seed changes `seed` and the `variations` block.
7. Every selected recipe's `transitionOut` is allowed by the style.
8. The plan's duration and aspect fit the format's declared durations and aspects, and the style's `limits.durations` and `limits.aspects`.
9. Every resolved `content.*` text slot is within the style's word limit.

A format may declare `sequence: [{ "beat": "...", "role": "...", "count": 1 }]` to repeat a role. This is how a 45-second, eight-spread book is built from four recipes without stretching any shot beyond its declared range. If `sequence` is absent, the resolver maps `beatRoleMap` once.

No renderer. This proves definition-level reuse and determinism.

Both resolve formats carry `beatRoleMap` and use only `BEAT_ROLES`.

## Blind protocol

1. Interview produces `styles/_briefs/keepsake.md`; it is frozen before scaffolding.
2. `npm run style:seal` builds `gate/blind/` with only: `_template/`, `STYLE-AUTHORING.md`, `prompt.md`, `brief.md`, `contract.json`, the validator and `SEAL.json` with hashes.
3. A fresh agent authors `keepsake` in `gate/blind/pack/`, may run the validator, and logs every question.
4. The result is copied to `styles/_examples/keepsake/`.
5. `style:check` compares the pack's bindings with `SEAL.json`. Any template or contract change invalidates the run and requires a new blind author.

Blind means blind to Paper K-pop and existing packs, not to the contract.

## Card

Required, one page, no dependencies. The top half must be judgeable before the fold.

| Section | Contents |
|---|---|
| `hero` | One specimen at output scale, the promise, feels / never feels |
| `legend` | REFERENCE, SPECIMEN, ANTI definitions |
| `visuals` | ≥1 REFERENCE, ≥1 SPECIMEN, ≥1 ANTI; no OUTPUT until S2 |
| `palette` | 4–6 chips with roles and usage |
| `type` | Display and body at relative size, licences, 390px smallest text |
| `motion` | CSS-only 6–10s loop of the signature move, plus a 390px phone frame |
| `sound` | One line: music character, or room tone / silence |
| `rules` | Five observable dos, three refusal examples |
| `fit` | Formats, aspects, max words, photo requirements, cost class |
| `proof` | Status, what is proven / not proven |
| `signoff` | `UNSIGNED` until `style:approve` rewrites the sign-off and every `data-status` marker |

The card also carries `data-status` markers. `style:approve` rewrites them to `APPROVED`, so the card can never say `REVIEWABLE` after approval.

The validator checks section presence, name, version and palette hexes. It also requires an `@font-face` rule for every declared type family file, and at least one `data-status`, one `data-waiting` and one `data-signoff` element. Approval refuses a card that lacks any of them. It does not judge layout or taste.

## Commands

```bash
npm run style:new -- keepsake --brief styles/_briefs/keepsake.md
npm run style:check -- styles/_examples/keepsake
npm run style:approve -- keepsake --by "Aakash"
npm run style:resolve -- --style ... --seed 42 --brief ... --format ...
npm run style:seal
```

Status ladder:

```
DRAFT       — missing required decisions or schema errors
REVIEWABLE  — zero hard failures, waiting for your eyes
APPROVED    — signed, pack hash matches
```

Exit code 1 only on hard failures. Warnings never block.

## Human report

```
STYLE: keepsake 0.1.0
STATUS: REVIEWABLE — machine-clean, waiting for your eyes

BEFORE YOU APPROVE (mechanical, 1)
1. Card type specimen uses a fallback font.
   Where: card.html > type
   Fix: use the declared face.

YOU MUST CHOOSE (taste, 1)
1. Page-turn speed: 0.8s / 1.2s / 1.6s.
   Brief says "slow". Which one?

WORTH KNOWING (1)
- Palette accent is used in only one recipe.

WHAT I COULD NOT CHECK
Taste, phone legibility, motion feel.

OPEN THE CARD: styles/_examples/keepsake/card.html

If you approve, run this yourself:
npm run style:approve -- keepsake --by "Your Name"

NEXT: paste everything above into your LLM and say

```

`DRAFT` includes schema errors such as a missing `transitionOut`; `REVIEWABLE` does not.

- After `style:approve`, status is `APPROVED`.
- Changing one byte after approval returns `REVIEWABLE — changed after approval`.
- The resolver passes all nine assertions.
- The mutation suite fails with a named rule for each of:
  1. missing required decision
  2. literal name or date in tokens or recipes
  3. engine term in tokens or recipes
  4. broken recipe-to-asset reference
  5. unknown slot
  6. invalid transition
  7. capability/recipe mismatch
  8. missing seed policy
  9. missing card section
  10. brief hash mismatch
  11. change after approval

## Simplicity constraints

- No new dependencies.
- One schema file, one CLI, one test file.
- Six authored artifacts per style plus recipes; `signoff.json` is generated.
- Template contains stubs and one generic recipe.
- Hard-fail only on what breaks reuse; warnings never block.
- No style diff, no second real style, no runtime implementation, no renderer.
- `styles/paper-vows` is legacy for S1a and is not expected to pass. S1b migrates it.
- The 27 rows are the ontology; the 12 questions are the author's surface.
